# Vision — Видение проекта KIS

> **KIS** — Кабинет Инвестиционной Стратегии.
> Файл описывает общее видение, цели и принципы проекта. Технические детали — в `arch.md`.
> Спецификация внешнего API брокера БКС — в `BCS-SPEC.md`.

## 1. Идея в одном предложении

Личный кабинет инвестора, который собирает данные со счетов всех брокеров в одном месте
и помогает выстраивать инвестиционную стратегию на месяцы и годы: портфель, инвест-идеи,
блоки активов, напоминания — через единый веб-клиент и набор независимых микросервисов.

## 2. Зачем это нужно

### 2.1 Практическая цель
У большинства частных инвесторов счета разбросаны по разным брокерам (БКС, Т-Инвестиции,
Газпромбанк, ВТБ, Сбер). У каждого брокера своё приложение и свой API. Хочется:

- **единую картину** — все активы, позиции и суммарный капитал в одном интерфейсе;
- **независимость от брокера** — свой UI, свои алерты, свои расчёты (доходность, allocation);
- **историчность** — брокеры не хранят историю котировок и снимков портфеля для клиента;
  собственный сервер данных позволит копить историю и строить графики/аналитику;
- **безопасность ключей** — refresh-токены брокеров хранятся на своих серверах, а не в браузере.

### 2.2 Образовательная цель
Проект создаётся в том числе как полигон для изучения технологий. Каждый сервис пишется
на языке/фреймворке, который интересно освоить: TypeScript + Fastify, Python, Go,
Java Spring. Это осознанное усложнение: разнообразие стеков заставляет продумывать
межсервисные контракты, формат обмена и деплой лучше, чем в монолите на одном языке.

Проект назван **KIS — Кабинет Инвестиционной Стратегии**.

## 3. Ключевые принципы

1. **Клиент не знает о брокерах.** Единственная точка входа веб-клиента — core-server
   (BFF). Экран «Портфель» — это один запрос к ядру, которое само опрашивает нужных
   брокеров, склеивает и конвертирует валюты. Клиенту всё равно, один брокер или пять.
2. **Единый контракт для брокеров.** Все брокерские серверы реализуют один и тот же
   внутренний REST-контракт (`contracts/broker-api`): одинаковые пути, JSON-схемы,
   ошибки. Добавить брокера = написать адаптер, ничего на клиенте не меняется.
3. **Тонкие адаптеры, умный контракт.** Вся «грязь» конкретного брокерского API
   (форматы токенов, пагинация, коды ошибок) остаётся внутри его сервера. Наружу —
   только нормализованные данные нашей модели.
4. **Один брокер — один сервис.** Серверы изолированы: падение или деградация одного
   брокера не влияет на остальных (graceful degradation экрана). Язык, база, деплой —
   у каждого свои.
5. **Данные рынка — общий ресурс.** Отдельный market-data-server собирает и кэширует
   котировки МосБиржи (только акции российских эмитентов), историю цен, курсы валют и
   иконки эмитентов. Остальные сервисы обращаются к нему, а не дублируют данные.
6. **Запуск одной командой.** Monorepo + Docker Compose: `docker compose up -d --build`
   поднимает всю платформу локально; на сервере обновление — `scripts/update.sh`
   (git pull + пересборка + rolling restart). Воспроизводимость важны и дома, и на VPS.
7. **MVP — минимальная вертикаль.** Первый рабочий срез: клиент → core-server →
   bcs-server → БКС API → портфель в браузере. Всё остальное наращивается итеративно
   поверх тех же контрактов.

## 4. Что входит в продукт (по стадиям)

| Стадия | Содержание |
|--------|-----------|
| MVP (v0.1) | web-client (React) + core-server (Java BFF) + bcs-server (Fastify): просмотр портфеля БКС по refresh-токену; docker compose |
| v0.2 | Второй брокер: tbank-server (Python FastAPI) — проверка, что клиент не меняется |
| v0.3 | market-data-server (Go): котировки MOEX, иконки эмитентов, курсы валют; обогащение портфеля |
| v0.4 | История: снимки портфеля в БД, графики доходности, карточка инструмента |
| v0.5 (KIS) | **Инвест-идеи**: карточки по акции (дата, целевая цена, тезис, горизонт), напоминания — по образцу практик вроде bcs-express.ru/investidei, но наши правила |
| v0.6 | **Блоки активов**: дивидендный, роста и т.п., с самостоятельным созданием и автоправилами; сортировки/группировки по отраслям и пользовательские |
| v1.0+ | Аутентификация пользователей, мультиброкерский дашборд стратегии, алерты по ценам |

Функциональное ядро будущего — именно «стратегическая» часть KIS: собрать данные со
всех счетов в одном месте и выстраивать инвестиционную стратегию на месяцы и годы
(карточки идей, блоки, отслеживание, напоминания). Как именно это будет выглядеть —
будет уточняться по мере роста проекта.

## 5. Нецели (осознанно вне скоупа)

- Автоторговля и исполнение заявок — пока только чтение данных (write-endpoints могут
  появиться далеко за MVP, и никогда из браузера напрямую).
- Хранение денег/персональных данных клиентов третьих лиц — платформа для себя,
  single-user на первом этапе.
- Повторение функциональности брокерских приложений (пополнение, ввод-вывод, налоги).
- Рынки, кроме МосБиржи: на первом этапе нас интересуют только акции российских
  эмитентов с фондового рынка MOEX (режим TQBR) — как на странице bcs.ru/markets.
  Облигации, фьючерсы, валюту и зарубежные площадки пока не трогаем.

## 6. Ожидаемый результат

Через несколько месяцев — работающий KIS: открываешь свой фронт, видишь консолидированный
портфель по всем брокерам (с иконками компаний и живыми ценами МосБиржи), ведёшь карточки
инвест-идей и блоки активов, получаешь напоминания по стратегии — при этом каждый
backend-сервис является отдельной учебной лабораторией со своим языком и стеком,
объединёнными общими API-контрактами, а вся платформа поднимается одной командой
`docker compose up -d`.
